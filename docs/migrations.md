# Alembic migration chain and duplicate-data safety

```
0001_baseline -> 0002_forge -> 0003_autonomous -> 0004_fencing -> 0005_budget_ledger -> 0006_budget_dispatch (head)
```

`app.db.migrations.upgrade_database(engine)` runs at application startup and in
`scripts/migration_smoke.py`. Databases with tables but no `alembic_version`
(pre-Alembic installs) are brought to the baseline shape with the conservative
add-missing-column pass, stamped `0001_baseline`, then upgraded normally.

## 0004_fencing was amended (why and how)

The original `0004_fencing` created two unique constraints directly:

- `uq_export_job_kind` on `exportartifact(job_id, kind)`
- `uq_storyline_job_option` on `storylinecandidate(job_id, option_index)`

A populated `0003_autonomous` database that already holds duplicate export
artifacts (an export stage re-run after a crash) or duplicate storyline
candidates fails the SQLite table rebuild with `UNIQUE constraint failed`,
leaving `_alembic_tmp_exportartifact` behind and the version at 0003. A later
revision cannot fix this because 0004 runs first, so **0004 itself was amended**
rather than adding a repair revision. Every step in 0004 is now guarded
(`has_table` / `_has_column` / `_has_unique`), leftover `_alembic_tmp_*` tables
are dropped first, and duplicates are resolved before each constraint is added.
The revision id is unchanged, so databases already at 0004 are unaffected and
databases stuck at 0003 (including half-applied ones) upgrade cleanly.

### Survivor rules (deterministic)

| Table | Group | Survivor | Losers |
| --- | --- | --- | --- |
| `exportartifact` | `(job_id, kind)` | newest **non-empty** artifact (`created_at` desc, then `id` desc); if all are empty, the newest | deleted (they are re-generated by an export re-run; the API only ever served the current one) |
| `storylinecandidate` | `(job_id, option_index)` | the `selected` row if any; else the non-rejected row with the highest `originality_score`; else the newest | **renumbered** to the next free `option_index` for that job — nothing is deleted because `autonomousnoveljob.selected_storyline_id` may reference any row |

The migration prints a one-line summary per table
(`[0004_fencing] exportartifact dedup: {...}`) containing counts only — never
titles, content or artifact bytes.

## 0005_budget_ledger

Adds the `budgetreservation` ledger table and the split reservation / cost
columns on `autonomousnoveljob` (`reserved_input_tokens`,
`reserved_output_tokens`, `reserved_cost_usd`, `cost_usd`,
`cost_unknown_calls`, `usage_estimated_calls`) plus `usage_reported` /
`max_tokens` on `modelinvocationattempt`. All new columns have server defaults,
so existing rows are backfilled with zeros. Pre-existing jobs therefore report
cost `unknown` (no priced calls recorded) rather than `0`.

## 0006_budget_dispatch

Adds `reserved_repair_calls` (integer, server_default 0) to `autonomousnoveljob`
and `dispatched_at` (datetime, nullable) to `budgetreservation`.
Pre-existing open ledger rows are conservatively transitioned to `dispatched`
so recovery never releases capacity that might have reached a provider.
Supports concurrency-hard CAS repair-call enforcement and conservative worst-case
charging of dead-worker in-flight requests.

## Tests

`backend/tests/test_migrations.py` covers, on SQLite:

1. fresh database -> head, no model/DB drift;
2. upgrade from **every** revision to head;
3. populated `0003` database with nulls and partially completed jobs;
4. duplicate export artifacts and duplicate storyline candidates;
5. a half-applied original 0004 (tables created, temp table left, version 0003);
6. idempotent re-application (`upgrade_database` twice);
7. legacy pre-Alembic database adoption;
8. application services (ORM, budget snapshot, job serialisation, startup
   recovery) against the upgraded populated file.

PostgreSQL: **not tested**. `DatabaseSettings.get_database_url()` only produces
SQLite URLs; PostgreSQL is not a configured deployment target of this tree.

## Adding a revision

```bash
cd backend
alembic revision --autogenerate -m "short description" --rev-id 000N_slug
python -m pytest tests/test_migrations.py -q    # includes the every-revision upgrade matrix
```

`check_schema_drift()` fails CI when a model change ships without a revision.
